# Console 代理相关 404 / 502 / 网关错误

> 路径:`Console /memos` 页面读不到 / 走 `MemosProxyEndpoint` 的请求报错。
> 涉及的代码:`MemosProxyEndpoint`、`MemosClient`、`WebClientConfig`。

## 症状速查

| 现象 | 大概率原因 | 见下文 |
| --- | --- | --- |
| Console 页面:"抓取失败: 401" | memos 关闭匿名 | [§1](#1-401-unauthorized) |
| "抓取失败: connection refused" | baseUrl 写错 | [§2](#2-connection-refused) |
| "抓取失败: timeout" | memos 慢 / 网络 | [§3](#3-timeout) |
| 控制台 502 | memos 5xx 或 body 解析失败 | [§4](#4-502-bad-gateway) |
| 列表能加载,附件图/视频 404 | 公开文件代理不通 | [§5](#5-附件图裂) |
| `MemosPage` 反序列化报 `UnrecognizedPropertyException` | memos 升级加字段 | [§6](#6-反序列化失败) |

---

## 1. 401 Unauthorized

**原因**:memos 实例未开启匿名访客访问。

**排查**:

```bash
sg docker -c 'docker exec halo-for-plugin-development \
  curl -sS -o /dev/null -w "%{http_code}\n" \
  http://172.17.0.1:5230/api/v1/memos?pageSize=1'
```

- `200` -> 不是这里的问题,继续看 §6。
- `401` -> 走下面任一修复。

**修复**:

- 方案 A(推荐):进 memos Web -> Settings -> System -> 勾 "Allow public visibility"。匿名即可。
- 方案 B:在 memos 里建 access token,填到 plugin-memos 设置的 `accessToken`。代码会自动加 `Authorization: Bearer ...`。

## 2. connection refused

**原因**:`baseUrl` 写错,或 memos 容器没在跑。

**排查**:

```bash
sg docker -c 'docker ps | grep memos'
ss -lntp | grep 5230
```

**修复**:

- 容器没起 -> `cd /www/server/panel/data/compose/memos && docker compose up -d`。
- 端口不对 -> `docker port memos` 查。
- baseUrl 用了 `127.0.0.1` -> **这是 Halo 容器自己**,换成 `http://172.17.0.1:5230`(bridge 网关)。

## 3. timeout

**原因**:memos 慢 / 网络丢包 / 单页附件太大超过 16MB。

**排查**:

```bash
sg docker -c 'docker exec halo-for-plugin-development \
  time curl -sS -o /dev/null http://172.17.0.1:5230/api/v1/memos?pageSize=20'
```

**修复**:

- 单次 > 5s:把 `pageSize=20` 调小(在 `MemosView.vue` 的 `PAGE_SIZE`),或优化 memos 服务。
- 内存超 16MB:在 `MemosView.vue` 中切换到"瀑布流"视图少加载,或调整 `WebClientConfig.maxInMemorySize`(谨慎)。
- 网络抖动:是临时问题就重试;持续高延迟,看 memos 日志。

## 4. 502 Bad Gateway

**原因**:`MemosProxyEndpoint` 收到 memos 5xx 后,**状态码被原样回传**,前端 axios 看到 502。

**排查**:

```bash
sg docker -c 'docker logs memos --tail 100'
```

**修复**:这是 memos 服务的问题,本插件没做重写。**本插件自身能做的**是改 `MemosClient.retryWhen` 加重试次数,临时缓解:

```java
.retryWhen(Retry.backoff(3, Duration.ofSeconds(2)))  // 2 -> 3
```

## 5. 附件图裂

**原因**:`/memos/proxy/file/**` 公开文件代理不通。

**排查**:

```bash
# 拿到一条 memo,取 attachments 里的 url
sg docker -c 'docker exec halo-for-plugin-development \
  curl -sS "http://halo:8092/memos/proxy/file/attachments/<uid>/<filename>" -o /dev/null -w "%{http_code}\n"'
```

**修复**:

- 404:文件名编码问题。`MemosMapper.resolveUrl` 用 `UriUtils.encodePathSegment` 编码,**中文文件名应该没事**;若仍有 404,看 memos 端附件原文件名是否有特殊字符。
- 502:同上 §4。
- 403 / 401:文件代理**不带 token**,走的是 `MemosProxyEndpoint.proxy` 同一段逻辑。若 memos 实例**要求**鉴权才能看附件,需要让公开代理也带 token —— 改 `MemosProxyEndpoint.proxy` 加 token 即可(见 `ai/backend/module-proxy-endpoint.md` 的"改 token 处理")。

## 6. 反序列化失败

**现象**:`MemosPage` / `MemoDto` 报 `UnrecognizedPropertyException`(或 `InvalidDefinitionException`)。

**原因**:memos 升级加了字段。`@JsonIgnoreProperties(ignoreUnknown=true)` 已加,理论上**新增字段不会失败**;但**删除 / 改类型**的字段会失败。

**修复**:

1. `docker logs memos | head -30` 看 4xx/5xx。
2. 临时把 `MemosClient.listPage` 改成 `bodyToFlux(JsonNode.class)`,手动 `log.info()` 看响应结构。
3. 同步 `MemosClient.MemoDto` 字段(类型 / 名字),加新字段。
4. 在 `ai/changelog/decisions.md` 写明 memos 版本变化。

## 调试技巧:加临时日志

```java
// MemosProxyEndpoint.proxy() 开头
log.info("proxy path={} -> target={}", request.path(), target);
```

观察日志,确认:

- `suffixAfterPrefix` 切分正确。
- 拼出来的 `target` 是合法 URL。
- 透传到 memos 的 `Authorization` 头是否带上。
